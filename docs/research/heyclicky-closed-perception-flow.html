🎙️ HOLD-TO-SEE

Straight from the binary: "I only see your screen when you press the hotkey." and "Nothing stays hot in the background unless you explicitly start it." There's no always-on recording — the microphone + screen capture only fire while you hold the shortcut. That's a deliberate privacy posture, not a technical limitation.

WHY IT'S ACCURATE

Clicky doesn't just crop a picture. It runs an AnnotationAccessibilityHarvester over the marked rectangle and passes the real underlying strings/URLs as text — "use these exact strings/URLs when relevant, don't re-read them from the image" — so the model quotes the actual price/label instead of misreading pixels.

The latency trick

Two models, one turn

This is the cleverest closed piece. A fast realtime model owns your voice and answers instantly with an acknowledgement only; a slower, stronger model actually looks at the annotated screenshot and answers. The binary literally logs "the model only spoke an acknowledgement."

speed lane · your ears

Realtime voice

  • Owns the mic while you hold the key (push-to-talk).
  • Transcribes your words in real time, says a short "mm-hm / on it."
  • On a screen question it does not answer — it just captures + acknowledges.
  • Speaks the final answer back in the skill's persona/voice.
wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1
smart lane · the eyes

"Higher model" via worker

  • Gets the annotated screenshot + gesture summary + AX harvest + transcript.
  • Produces the real, scoped answer and the visual-guidance "beats".
  • Routed through Clicky's own server, which holds the prompts + keys.
  • Background "do the work" tasks route to a hosted Codex thread.
POST api.heyclicky.com /chat-tool-call · Anthropic + OpenAI backends
ALSO

Plain dictation (hold fn+control, type clean text into any field) runs on a third path — Deepgram streaming (wss://api.deepgram.com/v1/listen, DictationDeepgramTranscriber.swift). So Clicky mixes OpenAI Realtime, Deepgram, and a server-side Anthropic/OpenAI "higher model" — picking the cheapest tool per job.

What I think about it

The moat is perception, not the driver

takeThey open-sourced the commodity

Computer-use drivers are becoming table-stakes (OpenAI CUA, Anthropic computer-use, trycua). Giving away the cua-driver skill costs nothing and buys goodwill — the "hands" are not where the value is.

takeThe real IP is the input grammar

Turning a sloppy trackpad scribble into a precise, AX-grounded region query — and doing it fast, with voice — is the genuinely hard, defensible thing. That's the entire clicky-closed tree, and it's exactly what they withheld.

takeThe server is the lock

Prompts, model routing, and the Codex threads live on api.heyclicky.com behind Supabase auth ("subscription paused until payment succeeds"). Closed binary + closed server = they keep the prompt engineering private and can meter/bill. Classic wrapper economics.

for cortexThis is our lane, not theirs

The read-across: don't compete on the driver. If Cortex builds a screen plane, the differentiator is the same — a great mark-and-ask perception layer + AX grounding + low-latency voice. Build that natively; treat Codex/the driver as swappable plumbing underneath.
